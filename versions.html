VERSION HISTORY

Keep the parts that work.

Compare earlier versions as working snapshots. For each change, mark what should be kept, reverted, reworked or reconsidered. Your choices become a precise brief for the next iteration instead of an all-or-nothing rollback.

Suggested loop
  1. Make one coherent release.
  2. Compare it with the previous release.
  3. Decide per change area.
  4. Copy the development brief.
  5. Build the next release from those decisions.
